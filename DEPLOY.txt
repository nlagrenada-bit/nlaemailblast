NLA Results API v1 integration  +  Lotto/Super 6 time fix
==========================================================

The web admin's API is quite different from the webhook we originally
specified, so the sender has been rewritten to match their documentation
("NLA Results API - v1", 7 Sep 2026 rev 5).

WHAT CHANGED VS OUR ORIGINAL DESIGN

  Old (our spec)                     New (their API)
  --------------------------------   --------------------------------------
  One POST for the whole day          One POST per game result
  Single URL /api/results-webhook     /omp/api/v1/results/{game}
  X-NLA-Signature header              Authorization: Bearer <token>
  Receiver upserts                    POST creates; 409 if it exists.
                                      Corrections require PUT to
                                      /results/{game}/{draw_number}
  -                                   Idempotency-Key for safe retries
  -                                   ?validate=1 dry run
  -                                   30 requests/minute per token

The sender now POSTs, and on 409 automatically falls back to PUT - so a
corrected result updates the stored record instead of failing.

ENVIRONMENT VARIABLES  (Netlify -> app site)

  REMOVE:  WEBSITE_WEBHOOK_URL, WEBSITE_WEBHOOK_SECRET

  ADD:     WEBSITE_API_BASE  = https://about.nla.gd/omp/api/v1
           WEBSITE_API_TOKEN = <the Bearer token for this client>

Then redeploy. Until WEBSITE_API_BASE is set the push is a no-op, so it is
safe to deploy before the token is in place.


DEPLOY
  git add -A
  git commit -m "Integrate OMP Results API v1; Lotto/Super 6 at 7:45pm"
  git push


TEST, IN THIS ORDER

  1. Ask the API what it expects next (proves auth + reachability):
       curl.exe -H "Authorization: Bearer $key" ^
         https://about.nla.gd/omp/api/v1/results/lotto/next

  2. Dry run from the app: enter a result, then use the send dialog's
     "Update the website/database only" option. Nothing is emailed.

  3. Check the result appeared in the OMP.


TWO THINGS TO WATCH

  * SEQUENCE VALIDATION. The API requires draw_number to be exactly
    last + 1. If our stored draw numbers are ahead of theirs, POSTs will
    return 422. Their /results/{game}/next endpoint tells you what they
    expect; an admin-scope client can send "allow_gap": true to backfill.

  * SCOPES. The token must cover every game we push. If it is scoped to
    only some games, the others return 403. Ask for "*" or all six.
